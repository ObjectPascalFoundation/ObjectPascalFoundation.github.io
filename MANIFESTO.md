# Object Pascal Foundation Manifesto

*Object Pascal is alive.*

It is used every day to build desktop applications, mobile applications, services, tools, embedded systems, scripts, libraries, games, research projects, educational material, and the quiet business software that keeps companies running.

It is also bigger than any one product, vendor, compiler, framework, or dialect.

[Delphi](https://www.embarcadero.com/products/delphi), [Free Pascal](https://www.freepascal.org/), [Lazarus](https://www.lazarus-ide.org/), [Oxygene](https://www.remobjects.com/elements/oxygene/), [PascalABC.NET](https://pascalabc.net/en/), [PascalScript](https://www.remobjects.com/ps.aspx), [DWScript](https://www.delphitools.info/dwscript/), [Smart Pascal](https://smartmobilestudio.com/), [Quartex Pascal](https://quartexdeveloper.com/), and the many related tools in this family do not all have the same goals. They should not have the same goals. Some optimize for native Windows productivity. Some optimize for open source portability. Some target managed runtimes, JavaScript, native platform APIs, scripting, education, embedded systems, retrocomputing, or specialized deployment models. That variety is a strength.

The Object Pascal Foundation exists to promote the whole ecosystem.

## A Family, Not A Fight

Developers do not benefit when every conversation becomes a contest over which tool is best.

Each Object Pascal implementation has strengths. Each has tradeoffs. Each grew out of different constraints, communities, platforms, and ideas about what developers need. A fair description of those differences is more useful than another argument.

We believe Object Pascal is strongest when its community can say:

- This is what our tool does well.
- This is where another tool may be a better fit.
- This is how these tools can work together.
- This is how Object Pascal connects to the rest of the software world.

Promoting one implementation does not require denigrating another. If the only way to make a tool look good is to make every other tool look bad, that is not confidence. The better argument is to show real strengths, real examples, and real working software.

## Interoperability Matters

Modern software is rarely built with one language, one runtime, one library, or one vendor.

Teams combine tools because different tools solve different problems well. A project might use a native UI, a Python automation layer, a C library, a C# service, a database engine, a JavaScript scripting language, and more APIs than anyone can count. This is normal. This is how software is built.

Object Pascal belongs in that mixed toolbelt.

Not because it needs other languages to be useful, but because it is useful enough to deserve a place beside them. Object Pascal has unique strengths: readable syntax, fast compilation, productive tooling, native application development, strong component models, mature libraries, and decades of production use. Interoperability makes those strengths easier to apply.

When Delphi makes it practical to put a native UI on an existing engine, that matters.

When Free Pascal reaches platforms and architectures that other tools ignore, that matters.

When DWScript or Smart Mobile Studio runs Object Pascal in the browser, that matters.

When [Quartex Pascal](https://quartexdeveloper.com/) reinvents the concept of a development platform, that matters.

When Oxygene brings Object Pascal ideas to .NET, Java, Cocoa, Android, native platforms, and WebAssembly, that matters.

When Pascal code can call C libraries, host Python, generate JavaScript, script an application, expose APIs, or sit inside a larger system, that matters.

These are not side stories. They are central to why Object Pascal remains useful.

## Promotion Without Regulation

The Object Pascal Foundation is not a standards body.

We are not here to tell implementers what language features they may add, what libraries they must support, what names they must use, or how compatible they must be. Language design involves tradeoffs. Platform support involves tradeoffs. Backward compatibility, innovation, performance, simplicity, tooling, and ecosystem fit all pull in different directions.

Those decisions belong to the people building and maintaining the tools.

The foundation's role is different:

- Collect what exists.
- Explain how it fits together.
- Promote useful work.
- Document interoperability.
- Help developers find resources.
- Encourage respectful collaboration.
- Make it easier for people outside the ecosystem to understand why Object Pascal still matters.

We can coordinate without regulating. We can compare without attacking. We can celebrate strengths without pretending differences do not exist.

## Evidence Over Slogans

Object Pascal does not need an apology tour. When people thought it "dead" it kept moving in the background.

It also does not need empty claims.

Good advocacy is specific. Show the source code. Show the benchmark. Show the project. Show the library. Show the integration. Show the build steps. Show the tradeoffs. Invite corrections.

Benchmarks and rankings can be abused. Everyone who has worked with statistics knows numbers can be made to say almost anything. That is why credibility comes from openness: clear criteria, visible source material, reproducible examples, and a willingness to fix mistakes.

The Object Pascal Foundation follows that model.

- If we say a tool exists, we link to it.

- If we say two systems interoperate, we show how.

- If we compare options, we describe the criteria.

- If we miss something, the community can open an issue or send a pull request.


The goal is not to win an argument by controlling the narrative. The goal is to make the ecosystem easier to understand.

## A Living Map

The Object Pascal ecosystem has decades of history and a lot of active work, but too much of it is scattered.

Some tools are well known inside one community and invisible to another. Some libraries solve real problems but are hard to find. Some interoperability examples exist only as forum posts, blog articles, demos, conference talks, or code in an old repository. Some projects are active but look abandoned because nobody has collected the current links. Some ideas are not promoted because they sit between vendor boundaries.

That is the gap this site aims to fill.

The Object Pascal Foundation is growing into a living map of:

- Implementations and dialects.
- Tools, IDEs, plugins, and editors.
- Libraries and components.
- Interoperability patterns.
- Education and learning resources.
- Books, videos, podcasts, and talks.
- Communities, forums, mailing lists, chats, and events.
- Historical context and modern examples.

This map is open to contribution. If something is missing, add it. If something is wrong, correct it. If a page is unfair, improve it. If an example is outdated, replace it with a better one.

## Implementation Map

The foundation's implementation map should be broad enough to include current, historical, commercial, open source, educational, embedded, scripting, web, and retrocomputing work. A complete list is always a living list, but the current Pascal and Object Pascal family includes:

- Native and RAD systems: [Delphi](https://www.embarcadero.com/products/delphi), [Free Pascal](https://www.freepascal.org/), [Lazarus](https://www.lazarus-ide.org/), [GNU Pascal](https://www.gnu-pascal.de/), [Virtual Pascal](https://en.wikipedia.org/wiki/Virtual_Pascal), and [TMT Pascal](https://pascal.sources.ru/tmt/help/language_def.htm).
- Managed, educational, and JVM/mobile systems: [Oxygene](https://www.remobjects.com/elements/oxygene/), [PascalABC.NET](https://pascalabc.net/en/), [Javascal](https://javascal.sourceforge.net/), and [MIDletPascal](https://midletpascal.sourceforge.net/).
- Web, JavaScript, and browser-targeted systems: [pas2js](https://wiki.freepascal.org/pas2js), [TMS WEB Core](https://www.tmssoftware.com/webcore/), [Smart Mobile Studio / Smart Pascal](https://smartmobilestudio.com/), [Quartex Pascal](https://quartexdeveloper.com/), [Elevate Web Builder](https://www.elevatesoft.com/products?category=ewb), and [DWScript](https://www.delphitools.info/dwscript/).
- Scripting and embeddable engines: [Pascal Script](https://www.remobjects.com/ps.aspx), [DWScript](https://www.delphitools.info/dwscript/), and [Modern Pascal](https://handwiki.org/wiki/Software:Modern_Pascal).
- Historical systems and early compiler lines: the original [CDC 6000 Pascal compiler](https://standardpascal.org/CDC6000pascal.html), [Pascal-P4](https://www.standardpascal.org/p4.html), [Pascal-P5](https://www.standardpascal.org/p5.html), [Pascal-P6 / Pascaline](https://standardpascaline.org/compiler.html), [UCSD Pascal](https://en.wikipedia.org/wiki/UCSD_Pascal), [Apple Pascal](https://en.wikipedia.org/wiki/Apple_Pascal), [JRT Pascal](https://en.wikipedia.org/wiki/JRT_Pascal), [Microsoft Pascal](https://en.wikipedia.org/wiki/Microsoft_Pascal), [Pascal/MT+](https://en.wikipedia.org/wiki/Pascal/MT%2B), and [Borland/Turbo Pascal](https://turbopascal.org/).
- Embedded, microcontroller, and retrocomputing systems: [mikroPascal](https://www.mikroe.com/compilers?programming-language%2A=pascal), [Turbo51](https://turbo51.com/about-free-8051-compiler), [Pic Micro Pascal](https://en.wikipedia.org/wiki/Pic_Micro_Pascal), and [Turbo Rascal Syntax Error](https://github.com/leuat/TRSE).
- Emerging and experimental Pascal-family work: [NitroPascal](https://nitropascal.org/) and [CPascal](https://cpascal.org/).

Some of these projects are active. Some are historical. Some are Pascal, some are Object Pascal, and some are Pascal-family dialects with their own goals. The point is not to flatten them into one standard. The point is to link them, describe them accurately, and make the family visible.

## Why This Matters

Object Pascal has always been practical.

It made structured programming approachable. It made native application development productive. It made visual component development a mainstream workflow. It taught generations of developers that readable code, fast feedback, and strong tools matter.

Those ideas are still relevant.

The software world keeps changing, but the need for productive, readable, reliable tools has not gone away. Developers still need to build applications. They still need to connect systems. They still need to ship maintainable software. They still need tools that help small teams do serious work.

Object Pascal can be part of that conversation.

Not as nostalgia.

Not as a vendor slogan.

Not as a tribal badge.

As a living family of languages, tools, libraries, and communities with real strengths and real software behind it.

## Our Invitation

If you build Object Pascal tools, tell us what they do well.

If you maintain a library, add it.

If you know an interoperability story, document it.

If you teach Object Pascal, share your material.

If you use Delphi, Free Pascal, Lazarus, Oxygene, PascalScript, DWScript, Smart Pascal, or another related tool, help us make the map better.

If you come from Python, JavaScript, C#, Java, C, C++, Swift, Kotlin, Rust, or any other ecosystem, you are welcome here too. Object Pascal does not need to replace the tools you already know and love. It can work beside them.

The Object Pascal Foundation exists to promote the ecosystem, connect the communities, and make the case with examples.

Object Pascal is alive, useful, modern, and still evolving.

Let us show it.
